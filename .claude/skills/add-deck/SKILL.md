# Add Deck

## Overview

A "deck" is a JSON file under `assets/decks/<language>/<level-or-category>/` that the app loads as a `Deck` (see `lib/data/models/deck.dart`). Adding one by hand requires several coordinated steps — get any of them wrong and the deck either fails to parse, doesn't ship in the app bundle, or never shows up in the deck list. This skill is the checklist for doing it right.

## Before you start: re-read the schema, don't assume it

The `Deck`/`Word`/`Sentence` models are still evolving (the `sentences` field and sentence-builder game mode were added recently, and existing deck files sometimes carry fields the models don't — e.g. `words[].meaning` is present in JSON today but not read by `Word`). **Never reuse field names from a previous session or from memory.** Every time this skill runs, read fresh:

- `lib/data/models/deck.dart` and `lib/data/models/word.dart` — for `Deck`/`Word`, `@JsonSerializable()` classes, so their `.g.dart` files (`deck.g.dart`, `word.g.dart`) are the ground truth for exact JSON key names and which fields are required vs. optional/defaulted.
- `lib/data/models/sentence.dart` — hand-written `fromJson`/`toJson` (not codegen), covers the `sentences` array.
- One existing deck file close to the new one's language/type, e.g. `assets/decks/chinese/hsk1/part1-5/chinese_hsk1_part1.json`, as a concrete shape reference — but verify every field against the model files above, since example files can drift ahead of or behind the models.

Deck/word `id` values in this repo are short human-readable slugs derived from the file path (e.g. `chinese_hsk1_part1`), not generated UUIDs — the `uuid` package here is used elsewhere (deck *editing* at runtime), not for static bundled deck content. Follow the slug convention unless the model files say otherwise.

## Workflow

1. **Place the file.** Follow the existing convention: `assets/decks/<language>/<level-or-category>/<descriptive_name>.json`. Look at `find assets/decks -type d` for the current layout before inventing a new branch of it.

2. **Write the JSON** against the schema you just re-read in step 0 — field names and types must match the `.g.dart`/model files exactly. Don't carry over stray fields from an example file unless the current model actually reads them.

3. **Register the asset directory in `pubspec.yaml`.** The `flutter.assets` list enumerates each deck leaf directory individually (it is not a recursive glob) — check `grep -n "assets:" -A 15 pubspec.yaml`. If this deck's directory isn't already listed, add it.

4. **(Optional, cosmetic) Add a display-name mapping.** `tool/generate_deck_manifest.dart`'s `_capitalize()` function maps known folder-name tokens (`chinese`, `hsk1`, `part1-5`, …) to nice display strings for the deck-picker UI. A new language/level folder not in that map still works (falls back to title-casing the raw folder name) but looks rougher — add an entry if it's a token worth naming properly.

5. **Regenerate the manifest**: run `make generate-manifest` (wraps `dart run tool/generate_deck_manifest.dart`). This rewrites `assets/decks/manifest.json` from whatever deck JSON files exist on disk — never hand-edit that file (a project hook blocks it anyway).

6. **Verify**: run `flutter analyze`, and run the deck-related tests — `flutter test test/data/models/deck_test.dart test/data/models/deck_manifest_test.dart test/data/models/word_test.dart` — to confirm the new deck parses and the manifest is well-formed.

## Quick Reference

| Step | Command / File |
|---|---|
| Schema source of truth | `lib/data/models/deck.dart`, `word.dart`, `sentence.dart` + their `.g.dart` files |
| Asset registration | `pubspec.yaml` → `flutter.assets` |
| Manifest regen | `make generate-manifest` |
| Verify | `flutter analyze` + `flutter test test/data/models/` |

## Common Mistakes

- **Hardcoding field names from a past run of this skill.** The models change; always re-read them fresh (see "Before you start").
- **Forgetting the `pubspec.yaml` asset entry.** `assets/decks/` is not recursive — a deck in a new directory is invisible to the app at runtime even though `flutter analyze`/tests pass, since those don't check the asset bundle.
- **Hand-editing `assets/decks/manifest.json`.** It's fully regenerated by `make generate-manifest`; edits are silently lost on the next run (and a `PreToolUse` hook in this repo blocks editing it directly).
- **Using a generated UUID for the deck/word `id`.** Static bundled decks use readable slugs, not UUIDs.
